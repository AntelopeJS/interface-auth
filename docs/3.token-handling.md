# Token Handling

The Interface Auth provides functions for generating and validating authentication tokens. These functions serve as the foundation for the authentication system.

## Token generation

### `SignRaw`

The `SignRaw` function signs arbitrary data and returns a token string.

```typescript
import { SignRaw } from "@antelopejs/interface-auth";

const token = await SignRaw(
  { userId: 123, role: "admin" },
  { expiresIn: "1h" },
);

// Return the token through your chosen authentication transport.
```

The function accepts two arguments:

| Argument  | Type                             | Description                   |
| --------- | -------------------------------- | ----------------------------- |
| `data`    | `string \| Buffer \| JsonObject` | The data to sign              |
| `options` | `SignOptions` (optional)         | Signing configuration options |

`JsonObject` maps string keys to JSON values (`string`, `number`, `boolean`, `null`, arrays and nested objects). A `Date`, a class instance or a function is a compile error: convert it first (for example `date.toISOString()`). A key whose value is `undefined` is accepted and dropped by serialization. An object typed with an `interface` has no index signature and is not assignable: declare it with a `type` alias or spread it into a literal.

`SignRaw` returns a `Promise<string>` that resolves to the signed token.

### `SignOptions`

The `SignOptions` interface configures token generation.

| Property    | Type                 | Description                                                                  |
| ----------- | -------------------- | ---------------------------------------------------------------------------- |
| `expiresIn` | `number \| TimeSpan` | Token expiration time as seconds or a timespan string (e.g., `"1h"`, `"2d"`) |
| `notBefore` | `number \| TimeSpan` | Duration before which the token is not valid                                 |

`TimeSpan` is the timespan grammar of the `ms` package: a number followed by an optional unit in any case, with or without a space (`"90"`, `"2h"`, `"7 days"`). A bare number string counts milliseconds. A string outside this grammar, such as `"soon"`, does not compile.

### `SignServerResponse`

The `SignServerResponse` function signs data and attaches the resulting token as a cookie on the HTTP response.

```typescript
import { SignServerResponse } from "@antelopejs/interface-auth";
import type { ServerResponse } from "node:http";

async function login(res: ServerResponse) {
  const userData = { userId: 123, role: "user" };

  await SignServerResponse(
    res,
    userData,
    { expiresIn: "1h" },
    { httpOnly: true, secure: true, path: "/" },
  );
}
```

The function accepts four arguments:

| Argument        | Type                             | Description                   |
| --------------- | -------------------------------- | ----------------------------- |
| `res`           | `ServerResponse`                 | The HTTP response object      |
| `data`          | `string \| Buffer \| JsonObject` | The data to sign              |
| `signOptions`   | `SignOptions` (optional)         | Signing configuration options |
| `cookieOptions` | `CookieOptions` (optional)       | Cookie configuration options  |

The cookie is set with the name `ANTELOPEJS_AUTH` and the signed token as its value. The function replaces the response's existing `Set-Cookie` header and returns a `Promise<ServerResponse>` that resolves to the same response object once the header has been set. It does not send or end the response.

### `CookieOptions`

The `CookieOptions` interface supplies attributes to the authentication cookie. The current serializer writes keys literally, omits `false` and `undefined`, writes `true` as a standalone directive, and converts other values with `String(value)`.

| Property   | Type      | Description                                                                     |
| ---------- | --------- | ------------------------------------------------------------------------------- |
| `maxAge`   | `number`  | Written as `maxAge=<number>`; not converted to the standard `Max-Age` attribute |
| `signed`   | `boolean` | Written as a directive when true; does not add a cookie signature               |
| `expires`  | `Date`    | Written using `String(date)`, not an explicit HTTP-date formatter               |
| `httpOnly` | `boolean` | Prevents client-side JavaScript from accessing the cookie                       |
| `path`     | `string`  | URL path for which the cookie is valid                                          |
| `domain`   | `string`  | Domain for which the cookie is valid                                            |
| `secure`   | `boolean` | Only sends the cookie over HTTPS                                                |

Do not rely on `maxAge`, `signed`, or `expires` for browser lifetime or extra signing guarantees in this implementation. Use a standards-compliant cookie serializer when those features are required, and keep token expiration in `SignOptions`. No cookie attributes are added by default.

`CookieOptions` has no `sameSite` field. If your deployment requires SameSite, serialize the cookie yourself and set the response header, as in the [authentication flow](./2.authentication.md#example-authentication-flow). Do not cast unsupported options into this type.

## Token validation

### `ValidateRaw`

The `ValidateRaw` function verifies a token and returns the data contained within it.

```typescript
import { ValidateRaw } from "@antelopejs/interface-auth";

async function inspect(token: string) {
  try {
    const claims = await ValidateRaw(token);
    console.log(claims); // { userId: 123, role: "admin" }
  } catch (error) {
    console.error(
      "Invalid token:",
      error instanceof Error ? error.message : String(error),
    );
  }
}
```

The function accepts two arguments:

| Argument  | Type                       | Description                |
| --------- | -------------------------- | -------------------------- |
| `token`   | `string` (optional)        | The signed token to verify |
| `options` | `VerifyOptions` (optional) | Verification configuration |

`ValidateRaw` returns a `Promise<AuthClaims>`, where `AuthClaims` is `string | JsonObject`: the signed string, or the JSON object that was signed. It has no type parameter. Read a field only after checking it, or hand the result to a parser of your own; a [custom verifier](./2.authentication.md#create-a-custom-verifier) is the place to do that once.

### `VerifyOptions`

The `VerifyOptions` interface configures token validation.

| Property           | Type               | Description                                          |
| ------------------ | ------------------ | ---------------------------------------------------- |
| `ignoreExpiration` | `boolean`          | If `true`, expired tokens are still considered valid |
| `ignoreNotBefore`  | `boolean`          | If `true`, tokens not yet valid are accepted         |
| `maxAge`           | `string \| number` | Maximum allowed age of the token                     |

### Example with verify options

```typescript
import { ValidateRaw } from "@antelopejs/interface-auth";

// Limit token age without bypassing expiration or not-before checks.
async function verifyRecent(token: string) {
  return ValidateRaw(token, {
    maxAge: "30m",
  });
}
```

Leave `ignoreExpiration` and `ignoreNotBefore` unset for normal authentication. They deliberately bypass time checks; use them only when you have a separate, explicit policy for accepting such tokens. A successful `ValidateRaw` verifies the token through your provider; it does not check the shape of the payload.
